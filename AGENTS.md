# CoFounderBay project guidance

- Use pnpm (root packageManager: pnpm@9.14.2). The frontend is Next.js/React in apps/web, not Vite.
- Frontend interaction tests: `pnpm --filter @cofounderbay/web test`.
- Frontend typecheck without changing tracked build metadata: `pnpm --filter @cofounderbay/web exec tsc --noEmit --incremental false -p tsconfig.json`.
- Vitest configuration lives in `.devin/vitest.config.ts`. Tests are adjacent `src/**/*.test.{ts,tsx}` files using jsdom and Testing Library. Native Node webstorage is disabled in test workers when the runtime supports that flag, so jsdom owns localStorage.
- These tests do not establish real-browser layout, contrast, native contenteditable behavior, or backend persistence correctness. Verify those separately.
- `pnpm --filter @cofounderbay/web build` shares the `.next` output with development. Do not run a production build over a user's running development server.
- The existing frontend lint script invokes `next lint`; no ESLint flat configuration was found during the UI review. Do not report lint as passing based on TypeScript or build output.
- Keep EN and EL content. Use existing BilingualText / LanguagePreferenceContext conventions; rules from other workspace projects using `useLanguage` are not this application's translation API.
- Preserve existing operations and routes during UI changes. Inspect actual API behavior before claiming that demo mode prevents writes, a delete removes related records, or an archive is reversible.
- Use the existing shared UI components, semantic colors, and radius/type tokens. Review replacements contextually rather than blindly mapping every color or size (brand colors, chart encodings and canvas data may have different purposes).
- Backend regression tests: `pnpm --filter @cofounderbay/api test`. Configuration is `.devin/vitest.api.config.ts`; it preserves NestJS decorator metadata with TypeScript transpilation. The jobs HTTP tests use mocked authentication, Prisma, queue, and providers; they do not prove production JWT verification, database persistence, or Redis behavior.
- Backend typecheck: `pnpm --filter @cofounderbay/api exec tsc --noEmit --incremental false -p tsconfig.json`.
- Script regression tests: `node --test scripts/deploy.test.cjs scripts/platform-inventory.test.cjs`. Deployment tests extract functions and stub external side effects; they never execute a deployment. Bash-dependent checks require Git Bash on Windows or `CFB_TEST_BASH`.
- Static platform inventory: `node scripts/platform-inventory.cjs --summary`; omit `--summary` for JSON containing route, boundary, interaction, and API declaration candidates. Every inventory entry starts as `not_tested`; static presence is not proof of functional, accessibility, or authorization coverage.
- Rendered platform sweep: `node scripts/platform-sweep.mjs [routes.txt] [width]` against a running dev server. One row per static route — HTTP status, uncaught errors, horizontal overflow, unnamed controls, Greek share, Ask AI seam, sample-data notice, dead bands — plus a summary. It signs in as `platform_admin` in demo mode via cookies/localStorage, so it measures what that role sees at one width; it is not an authorization test. `docs/PLATFORM_DESIGN_AI_PLAN.md` §21.3 records a full run. Compiling 142 routes on first hit takes the dev server several minutes and slows jsdom tests running concurrently to the point of 60s timeouts — do not run both at once and call the timeouts a regression.
- The assistant's capabilities are declared once in `packages/shared/src/actions/` and executed per app. `ACTION_DECLARATIONS` uses `as const satisfies` so `MutationActionId` and `UndoableActionId` stay literal unions; the web app keys `EXECUTORS`/`UNDOS` off them, so declaring a mutation without an executor, or claiming `full`/`partial` reversibility without an undo, is a compile error. Read `getActionDeclaration`/`listDeclarations` for the widened shape — the `as const` gives read actions no `reversal` key at all, so the literal union cannot be dotted into.
- Never state a `reversal` from intent. Read the controller first. `send_connection` is `partial`: `DELETE /connections/:connectionId` (`withdrawRequest`) lets only the sender withdraw, only while the request is `pending` (409 once answered), and the receiver was already notified. `start_or_send_message` stays `kind: 'none'` because `getOrCreateDirectConversation` cannot report whether it created the thread. A wrong claim here shipped once already, in each direction.
- `packages/shared` is consumed through its gitignored `dist`, so run `pnpm --filter @cofounderbay/shared build` before typechecking either app. Both vitest configs alias `@cofounderbay/shared` to `src/index.ts` so the test commands work on a fresh clone without that build; turbo's `dev` and `build` both depend on `^build`.
- The migration history is not how this database is provisioned: `apps/api/prisma/migrations` creates 63 tables while `schema.prisma` declares 187 models. `SavedProfile` (shortlist), `AIUsageLog` (written on every `/ai/chat`), `AIConversation` and `AuditLog` are all schema-only, so `prisma db push` is what makes them exist. Do not hand-write a migration for one unmigrated model: it would fail on an already-pushed database and imply the history is authoritative. Verify a table's real existence before claiming a feature persists.
- Controller tests must spy the guard prototype, not just provide it: `{ provide: JwtAuthGuard, useValue: … }` does not intercept, because the real guard extends passport's `AuthGuard('jwt')` and answers 500 with no strategy registered. Use `vi.spyOn(JwtAuthGuard.prototype, 'canActivate')` in `beforeEach`, and reinstall it every test since `restoreMocks` is on.
- PageRail rule: a control lives in the column or the rail, never both. `pageRailContract.test.ts` fails on a label rendered in both places (catalogue keys, `en=` props, `label=` props); the shared-text allowlist documents the rare legitimate exceptions (context menus, toast text). `usePageRail().openRailSection(id)` opens the rail imperatively - peek on desktop, sheet below `lg` - for shortcuts, commands and assistant actions.
- `apps/api/src/ai/tool-calls.ts` is the server's enforcement point: it validates a model's `tool_calls` against the same declarations `GET /ai/tools` serves. It never executes anything — accepted calls travel back as proposals and carry `writes` so a caller cannot treat a mutation as a read. It is not an authorization check; each endpoint keeps its own guards.
- App chrome is mounted once per section by `AppShellFrame` in segment `layout.tsx` files. `<AppShell>` detects the frame via context and renders only the page header (bilingual title, glyph, Ask AI, help) plus body; outside a frame it wraps itself in one. Do not mount a second `AppShellFrame` inside a framed section — that nests a full second chrome inside `<main>`. `/messages` is the only `fullHeight` frame; `/ai` keeps no layout because a single-page section gains nothing from persistence.
- Page rail: a page declares `const rail: PageRailSection[]` and passes it as `<AppShell rail={rail}>` (`/research/[boardId]` mounts `<PageRail>` itself, having its own chrome). A control moves to the rail, it is never copied: `pageRailContract.test.ts` fails on a shared label *or* on rail-shown state (`aria-pressed`/`value`) that a column control also binds. The mounted rail publishes its section ids/labels/badges (never content) to `PageRailContext`, the assistant's page-context packet carries them as `rail.sections`, and `open_rail_section` opens one. `node scripts/rail-candidates.mjs` lists pages that may need a rail and the ones declined with a reason.
- Dead controls are a test failure: every `<Button>` and menu item needs a handler, a link (`asChild`), a form to submit, `disabled` (the test cannot check the reason: give one via `title` or `UnavailableMenuItem`), or a Radix trigger `asChild` wrapper (`deadControls.test.ts`); every internal `href`/`router.push` must match a `page.tsx` (`internalLinks.test.ts`).
- Optional-chain discipline for partial API payloads: guard every level (`a?.b?.c`), including before `.length`/`.map`/`.filter`/`.find` and before method calls on the leaf. `a?.b.c` still throws when `b` is absent — this class blanked whole routes once already.
- The e2e axe suite (`pnpm --filter @cofounderbay/web run test:a11y`) needs `pnpm exec playwright install chromium` once and a production build; it spins up `e2e/mock-api.mjs` plus `next start` itself. `NEXT_PUBLIC_API_URL` is interpolated into the CSP `connect-src` at build time — unset in production builds makes the app block its own API calls.
- `frame-src` cannot be narrowed to named hosts: the research canvas and PDF annotation viewer iframe arbitrary user URLs (https, http, blob:).
- Keep `apiRequest` as a named export from `apps/web/src/lib/api.ts` for existing clients. `apiFetch` shares authentication and CSRF handling for non-JSON transports. Never automatically repeat an AI POST after partial streaming output or an authorization/rate-limit error.
- Page controls: a page offers its own filters, periods, exports and row commands to the assistant with `usePageControls([...])` (`apps/web/src/lib/page-controls.ts`), passing the same handlers its buttons call. `writes: false` runs only through `use_page_control`, `writes: true` only through `run_page_command` (`reversal: partial`), so the confirm card's warning always matches what ran. A command may name its verified opposite with `undo: (value) => ({ control, value }) | undefined`, asked before it runs so the page answers from the row's current state; Undo then runs that control on the same row. Name one only after reading the endpoint: it must restore exactly what the command changed (moderation and role writes set one field; completing a milestone also sets progress, so it has none; removing a shortlist row loses its note, so it has none). Every page with controls also publishes its visible rows with `usePageList` (or is in the test's reasoned `NO_LIST`), and every row-menu handler is reachable as a command or listed with a reason. Put `unavailableEn/El` on a control that cannot run (sample rows, nothing to export) rather than leaving it out; the executor then refuses with that reason. Call the hook before any early return: `pageControls.test.tsx` fails on a component-level `return` above it, because lint does not run here. `pageRailContract.test.ts` ignores `usePageControls` blocks since they render nothing.
- Query keys: build every key with `qk(root, ...rest)` from `apps/web/src/lib/query-keys.ts` (or a named entry of `queryKeys`); `root` must be one of `QUERY_ROOTS`, one per resource, and a part of a resource is the second segment (`qk('research-boards', 'versions', boardId)`) so the resource's invalidation reaches it. `queryKeyFactory.test.ts` fails on an array-literal key outside that file and on any write (invalidate/cancel/refetch/remove/set, a server `seed`) that no query key can match - that is how a restored canvas version stayed stale. `queryKeyCoherence.test.ts` still fails when one `api.*` read is cached under two roots.
- Rail anatomy: build rail content from `components/layout/RailParts.tsx` (`RailStats` for figures, `RailOptions` for one-of-many filters with `aria-pressed` and optional counts, `RailAction` for clear/export) instead of per-page copies. A rail needs at least two genuine sections (`pageRailContract.test.ts`); a page whose only auxiliary content is a count strip keeps it in the column (/connections). When a rail filter can empty the list, the empty state says so and offers `openRailSection('filters')`, never a second copy of the rail's control.
- `SampleDataNotice` renders as a pill in the page header through `PageHeaderSlot` when inside `AppShell`; it takes no body row there.
- Sample rows are gated on `useDemoData().showDemoData`, draw their people from the demo world (`lib/preview-api.ts` PEOPLE, `lib/demo/org-world.ts`) in the roles it gives them, never name a real fund or company, and carry ages rather than dates: stamp them after mount (`useEffect(() => setNow(Date.now()))`), because a date computed while prerendering disagrees with hydration. A sample's profile/message actions are `disabled` with a `title` saying why.
- Normalise partial payloads at the client boundary in `lib/api.ts` (`toProgramItem`, `breakdownText`, the SSO list/config readers always return arrays / a shaped config, `getProgram` throws without an id) rather than guarding in every page.
- Read the signed-in user with `useStoredUser()` (after mount), never `localStorage` during render: server and first client render must agree.
- Stop a production server only through `/proc/*/comm` matching `next-server*`. `pkill -f "next start -p 3000"` inside a command that itself contains that string kills the invoking shell.
- Toasts: call sites pass English; the Greek lives in `apps/web/src/lib/i18n/strings-toasts.ts` and `ToastItem` looks it up at render time. `toastCatalog.test.ts` fails on a literal toast title or description with no entry — add the Greek there rather than wrapping the call site.
- Status, role and category values from the API render through `StatusText` / `statusEl` (`components/common/StatusText.tsx`); a new enum value gets its Greek in that map. `RelativeTime` switches `formatRelativeTime` and date-fns to Greek for a Greek reader, so pass the shared formatter rather than a local copy.
- Most pages are statically prerendered, so a date computed from "now" during render is frozen at build time and fails hydration (#418) once the reader's day differs. Wait for the client (`useHydrated`, or stamp after mount). `node scripts/clock-probe.mjs [routes] [days]` runs every route with the browser clock shifted; any route it lists is freezing a date.
- An `sr-only` (absolutely positioned) element inside a horizontal scroller needs a positioned ancestor inside that scroller, or it escapes the scroller and widens the page on phones (`phone-layout.spec.ts` catches it).
- `/admin/dashboard` is the platform overview (figures, health, what needs attention); `/admin` is the console (tabs that act). Link, do not duplicate, between them.
- Forms as proposals: `draft_milestone`/`draft_event`/`draft_project`/`draft_profile` write nothing (`writes: false`, `invalidates: []`). The executor stashes only the declared fields with `stashFormDraft` (sessionStorage, taken once, ignored after 10 minutes) and opens `FORM_DRAFT_ROUTES[id]`; the form calls `useFormDraft(id, apply, ready)` after its own values load and shows `FormDraftNotice`. Nothing is saved until the person presses the form's submit button.
- Role gating: a declaration's `roles` lists the platform roles that may use it; `toToolCatalog(role)`, `GET /ai/tools` and `reviewToolCall(raw, role)` filter on it, and the web engine refuses the same tools with a bilingual reason. It mirrors the endpoints' guards for the model's sake; the endpoints stay the authorization.
- `lib/copilotEval.fixture.ts` holds 60 EN/EL requests and `copilotEval.test.ts` holds the planner at ≥95% overall and per language. The set is self-authored: a planner change that passes it is evidence, not proof, of what real people type. Add a failing phrasing to the fixture before fixing the planner.
- `node scripts/ai-coverage.mjs` is the census of what the assistant can operate per page; every page it reports as not operable needs a reason in `scripts/ai-coverage-reasons.json` (`aiCoverage.test.ts` fails on a missing or stale reason).
- The left sidebar folds to a rail with its edge button and, collapsed, opens over the page while a mouse rests on it (180ms intent delay; touch and pen never peek). Escape or navigation closes the peek and holds it closed until the pointer leaves, because the reflow fires a fresh `pointerenter`. `e2e/navigation-chrome.spec.ts` covers it.
- Decorative-icon CSS (globals.css, "Decorative icons"): a glyph beside a visible label, or inside a card, is hidden; an icon-only control keeps its icon. A child counts as a label only if it is not the svg, not `.sr-only` and not `.hidden` (a `hidden sm:inline` label is gone on phones). The well an in-card icon sat in is hidden with it; state glyphs (check, circle, lock, spinner) and anything inside `[data-keep-icon]` (content such as achievement badges, avatar fallbacks) stay. Never nest `:has()` — one invalid selector drops the whole rule silently. `decorativeIcons.test.ts` guards the selectors; the sweep's `blankIcons` column and the e2e spec measure the result.
- Below 640px `BilingualText` shows one language unless `keepSecondaryOnMobile`, so a 0% Greek share on a phone is the design; `platform-sweep.mjs` prints `n/a` there.
- `next.config` sets `reactRemoveProperties` in production, which strips every `data-test*` attribute. The e2e suite runs a production build, so locate by role and name (`getByRole('dialog', { name })`), never `getByTestId`; other `data-*` hooks (`data-sidebar-edge-toggle`, `data-peek`) survive.
- Theme tokens: `apps/web/scripts/check-theme-contrast.py` must report 0 (the a11y suite runs it). A light fill in a dark context takes a dark ink label of its own hue rather than a darker fill, so the brand hue stays; dark role overrides are written `html.dark.role-*` and the script reads them.
- Corners: one ladder from `--radius` (14px) in `tailwind.config.ts` — `sm`/`DEFAULT` 6 (marks, kbd, checkbox), `md`/`lg` 10 (buttons, fields, chips, rows), `xl` 12 (tiles inside a card, menus), `2xl` 14 (cards, dialogs, sheets), `3xl` 18. A clickable control takes `rounded-md`, never bare `rounded` (that is the 6px mark step). No arbitrary `rounded-[…]` outside the contribution heatmap.
- Emphasis surfaces: `border-primary/15 bg-primary/[0.03]`, flat. `calmSurfaces.test.ts` fails on any brand/status/accent gradient in `src/app` or `src/components` (exceptions: the landing hero's clipped text gradient, the alliance theme preview). Selected/active/drag states keep their own stronger edge; this rule is for decoration.
- Status tones sit at ~21 chroma (S × (1 − |2L − 1|)) in light themes and ~16 in dark; the brand ~30/22; neutrals ≤5. Measure a new tone against its band and its own tint's contrast before adding it.
- globals.css restates `.p-2…p-6`, `.px-*`, `.py-*` and the standard side utilities in px from 1024px up, *after* Tailwind's utilities. An arbitrary side value (`pl-[3.75rem]`, `pb-[calc(…)]`) next to a `p-N` therefore loses at desktop. Write the sides separately (`py-3 pr-3 pl-[3.75rem]`).
